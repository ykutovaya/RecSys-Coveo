# Запуск и воспроизведение

[English](/documents/en/reproduction.md) | Русский

Команды выполняются из корня проекта в PowerShell. Проверенная среда — Windows,
Python 3.11; зависимости закреплены в [uv.lock](/uv.lock).
Установка и проверки — в [README](/README.ru.md#установка-и-запуск).

Средства подготовки настроек и подтверждений допуска включены в репозиторий.
Команды ниже позволяют получить модель и отчёт C_smoke из трёх CSV без прежних `runs/`.
Проверка всего расчёта на небольшой реальной выборке завершена 11 октября 2026 года
после отдельной установки из wheel без привязки к исходникам. Из внешних файлов понадобились только три исходных CSV.
Готовые данные, модели и каталоги `runs/` в Git не входят.

При локальной проверке `uv sync` взял устаревшую сборку пакета из кеша.
Установка из актуального wheel проверена отдельно. Если после изменения
исходников CLI использует старый код, из корня проекта пересоберите только этот пакет:

```powershell
uv build --no-build-isolation
uv pip install --python .venv/Scripts/python.exe --no-deps --reinstall `
  dist/coveo_recsys-0.1.0-py3-none-any.whl
```

Перед этим установите зависимости командой `uv sync` из README. При смене
версии проекта используйте имя нового wheel; удалять весь кеш не требуется.

## Локальная демонстрация

### Необходимые входы

[Настройки сервиса](/configs/coveo_service.json) закрепляют завершённый эксперимент
на 300 кандидатах. Сервису нужны:

| Вход | Как получается |
|---|---|
| `runs/coveo-historical-ag50000-v1/` | `historical build` из подготовленного A_G |
| `runs/coveo-b50000-ranker-v2/` | `train ranker`: модель и `reports/ranker.json` |
| `runs/coveo-b50000-features-v2/reports/features.json` | Сводка `features build`, связанная с моделью; полные таблицы признаков сервису не нужны |
| `data/01_raw/sku_to_content.csv` | Исходная поставка Coveo |
| Профиль поставки, схема признаков и шаблоны объяснений | Файлы репозитория, закреплённые в настройках сервиса |

На компьютере автора эти файлы уже есть. В чистом клоне их сначала нужно
получить; модель для скачивания не опубликована. Для собственного расчёта берите
пути и контрольные суммы из его результатов, а не из старого запуска.
Сервис проверяет связь модели с пакетом, признаками и метаданными.

### Запуск сервиса

В первом терминале задайте непустой секрет локального отправителя. Его значение
потребуется и во втором терминале; оно не должно попадать в Git или пример ответа.
Для каждого запуска используйте новый `run-dir`.

```powershell
$env:COVEO_LOCAL_TOKEN = Read-Host 'Секрет локального отправителя'
uv run --no-sync coveo-recsys serve `
  --config configs/coveo_service.json `
  --run-dir runs/local-demo-v1 `
  --host 127.0.0.1 --port 8000
```

Текущий календарь сервиса заканчивается **1 января 2027 года, 00:00 UTC**.
Перед более поздней демонстрацией задайте допустимый календарь в отдельной
локальной копии настроек и передайте её в `--config`; не меняйте исторические
периоды обучения. События вне календаря отклоняются. Остановка сервера — `Ctrl+C`.

### Запрос

Во втором терминале отправьте пример запроса с действительным SKU из исторического
каталога. Он имитирует просмотр товара и обращается к готовой модели,
но не воспроизводит покупательскую сессию и не оценивает качество рекомендаций.

```powershell
$env:COVEO_LOCAL_TOKEN = Read-Host 'Тот же секрет локального отправителя'
$uri = 'http://127.0.0.1:8000'
$headers = @{Authorization="Bearer $env:COVEO_LOCAL_TOKEN"; 'X-Stream-Complete'='true'}
Invoke-RestMethod "$uri/health/ready"

$sid = [guid]::NewGuid().ToString('N')
$eventTime = [DateTimeOffset]::UtcNow.ToUnixTimeMilliseconds()
$event = @{
  source_namespace='local-demo'; session_id=$sid; event_id='e1'
  event_time_ms=$eventTime; event_type='detail'
  sku='0005c742138a6bf913d314c829f41ff2d8e665e9b3670b7b337a9d59b7cff34d'
} | ConvertTo-Json -Compress
$events = '[' + $event + ']'
$sha = [Security.Cryptography.SHA256]::Create()
try {
  $digest = -join ($sha.ComputeHash([Text.Encoding]::UTF8.GetBytes($events)) |
    ForEach-Object { $_.ToString('x2') })
} finally { $sha.Dispose() }
$head = @{
  source_namespace='local-demo'; session_id=$sid; event_time_ms=$eventTime
  block_id='b1'; event_count=1; event_ids=@('e1'); payload_sha256=$digest; closed=$true
} | ConvertTo-Json -Compress
$body = $head.TrimEnd('}') + ',"events":' + $events + '}'
Invoke-RestMethod "$uri/v1/blocks" -Method Post -Headers $headers `
  -ContentType 'application/json' -Body ([Text.Encoding]::UTF8.GetBytes($body))

$query = @{
  source_namespace='local-demo'; session_id=$sid
  trigger_block_id='b1'; idempotency_key='q1'
} | ConvertTo-Json -Compress
$response = Invoke-WebRequest "$uri/v1/recommendations" -Method Post -Headers $headers `
  -ContentType 'application/json' -Body ([Text.Encoding]::UTF8.GetBytes($query)) `
  -UseBasicParsing
$answer = [Text.Encoding]::UTF8.GetString($response.RawContentStream.ToArray()) |
  ConvertFrom-Json
$answer | Select-Object query_id, items, branch, delivery, reasons | ConvertTo-Json -Depth 5
```

`payload_sha256` вычисляется по точным байтам массива `events`, который отправляется
в теле. Ответ явно читается как UTF-8: это сохраняет русский текст объяснений
в Windows PowerShell 5.1. `X-Stream-Complete` подтверждает завершение передачи блока отправителем;
это не утверждение о полноте исторической телеметрии Coveo.

## Порядок полного расчёта

Команды проверяют воспроизведение базового расчёта до C_smoke, но не повторяют
опубликованные результаты D. Варианты без метаданных и на 370 кандидатах,
C_select, D и сервис сюда не входят. Прежние данные и модели не меняются.

Повтор `historical build` использует только полностью опубликованные
совместимые части. Если запись отдельного артефакта прервалась до завершения
дескриптора и его контрольной суммы, команда требует новый каталог запуска.
Оставшиеся файлы не удаляются и не перезаписываются автоматически; завершение
такой публикации в прежнем каталоге не поддерживается.

### Данные и пределы

Получите Public Data Release 1.0.0 по [инструкции Coveo](https://github.com/coveooss/SIGIR-ecom-data-challenge#license),
приняв условия самостоятельно. В `data/01_raw/` нужны `browsing_train.csv`,
`search_train.csv`, `sku_to_content.csv`; архив переносить не требуется.
Схема и ожидаемые контрольные суммы — в [профиле](/configs/coveo_supply_v1.json).

Согласованный 11 октября 2026 года малый запуск: до **2 000 сессий A_G,
2 000 B и 1 000 C_smoke**;
на вычислительную команду — 1 час, 4 ГиБ памяти, 4 ГиБ временных файлов,
2 ГиБ результата там, где команда поддерживает такой предел.
Все пределы соблюдены; [измерения ниже](/documents/reproduction.md#результат-малого-прогона).
Даже для небольшой выборки нужно прочитать большие CSV.

У `data prepare` параметр `max_temp_bytes` ограничивает временные файлы,
но отдельного ограничения размера готовых таблиц нет. Историческая сборка,
признаки, обучение и `replay` проверяют собственный предел результата.
Расход диска при подготовке нужно контролировать отдельно.

Выполняйте команды последовательно; при ошибке не переходите к следующему шагу.
Для нового расчёта используйте новый `$work`. `$csv` может указывать на внешний
каталог с теми же тремя файлами: копировать CSV в чистый клон не требуется.

```powershell
$python = '.\.venv\Scripts\python.exe'
$cli = '.\.venv\Scripts\coveo-recsys.exe'
$work = 'runs/reproduction-small-v1'
$csv = 'data/01_raw'
$helper = @(
  '-m', 'coveo_recsys.verification.reproduce',
  '--work-dir', $work, '--input-dir', $csv,
  '--max-result-bytes', '2147483648'
)
$prepare = @('--input-dir', $csv, '--profile', 'configs/coveo_supply_v1.json')

& $python @helper init --ag-sessions 2000 --b-sessions 2000 --smoke-sessions 1000 `
  --max-seconds 3600 --max-memory-bytes 4294967296 --max-temp-bytes 4294967296
if ($LASTEXITCODE -ne 0) { throw 'Планы не созданы' }
```

`init` создаёт `A_G-plan.json`, `B-plan.json`, `C_smoke-plan.json`.
Периоды, seed 17, цель `observed_purchases_v1` и отбор целых сессий сохраняются.
Размер задаётся до анализа покупок; недобор допустим только при недостатке
подходящих сессий, не ради изменения состава целей.

### Проверки кода до чтения CSV

```powershell
& $python @helper tests
if ($LASTEXITCODE -ne 0) { throw 'Нет полного результата обязательных проверок' }
```

Команда запускает обычный pytest без Coveo и нагрузки, сохраняет JUnit,
статистику свойств и состав исходников в `$work/tests/`. Старые результаты
не подставляются. После этой команды код и настройки в репозитории не меняйте.

Для локального допуска на Windows разрешены только явно перечисленные пропуски
тестов символических ссылок по причине `WinError 1314`; они остаются `skipped`
в JUnit и сводке и не считаются успешными проверками. На Ubuntu эти тесты
обязательны. Другие пропуски, ошибки и изменение исходников запрещают продолжение;
правило закреплено в [ТЗ §15.1](/documents/implementation_spec.md#151-общий-порядок).
В чистом каталоге `runs/reproduction-clean-v1/` проверена установка из wheel без привязки к исходникам:
пакет загружен из `site-packages`, его код совпал с исходниками. Полный pytest
без Coveo и нагрузки завершён за 308,73 с: 2 150 проверок пройдены,
8 проверок символических ссылок пропущены по согласованному правилу,
1 проверка исключена маркером. Состав проверок к `preflight` и `post_training`
подтверждён; это ещё не допуск данных и не результат оценки C_smoke.

### A_G, исторический пакет и B

```powershell
& $cli data prepare @prepare --plan "$work/A_G-plan.json" `
  --run-id reproduction-small-ag --run-dir "$work/a_g"
if ($LASTEXITCODE -ne 0) { throw 'Подготовка A_G не завершена' }
& $python @helper check-ag
if ($LASTEXITCODE -ne 0) { throw 'A_G не прошёл независимую сверку' }
& $python @helper historical
if ($LASTEXITCODE -ne 0) { throw 'Настройки исторической сборки не созданы' }
& $cli historical build --config "$work/historical.json" `
  --run-id reproduction-small-historical --run-dir "$work/historical"
if ($LASTEXITCODE -ne 0) { throw 'Историческая сборка не завершена' }

& $cli data prepare @prepare --plan "$work/B-plan.json" `
  --run-id reproduction-small-b --run-dir "$work/b"
if ($LASTEXITCODE -ne 0) { throw 'Подготовка B не завершена' }
& $python @helper check-b
if ($LASTEXITCODE -ne 0) { throw 'B не прошёл независимую сверку' }
```

`check-ag` и `check-b` сверяют общие таблицы с опубликованными строками выбранных
сессий: временные границы, первый запрос, префикс, цели и разделение периодов.
Рабочие канонизатор и расчёт целей не используются как эталон. Повторная проверка
не требует прежнего B на 10 000 сессий или посессионных файлов.

### Допуск, признаки и модель

```powershell
& $python @helper features
if ($LASTEXITCODE -ne 0) { throw 'Допуск preflight не получен' }
& $cli features build --period B --config "$work/features.json" `
  --run-id reproduction-small-features --run-dir "$work/b_features"
if ($LASTEXITCODE -ne 0) { throw 'Расчёт признаков не завершён' }

& $python @helper train
if ($LASTEXITCODE -ne 0) { throw 'Настройки обучения не созданы' }
& $cli train ranker --config "$work/train.json" `
  --run-id reproduction-small-ranker --run-dir "$work/ranker"
if ($LASTEXITCODE -ne 0) { throw 'Обучение не завершено' }
```

`features` формирует `preflight` по результатам проверок нового запуска и создаёт
настройки. `train` закрепляет готовые признаки; сама модель обучается отдельной
командой. Квоты на 300 кандидатов, схема признаков и рецепт LightGBM не меняются.
Если нет целей или обучающих пар, не увеличивайте выборку по увиденным покупкам:
сохраните результат отказа и отдельно согласуйте размер новой выборки.

### C_smoke и отчёт

```powershell
& $python @helper evaluation-preparation
if ($LASTEXITCODE -ne 0) { throw 'Допуск post_training/evaluate не получен' }
& $cli data prepare @prepare --plan "$work/C_smoke-plan.json" `
  --evaluation-config "$work/evaluation-preparation.json" `
  --run-id reproduction-small-csmoke --run-dir "$work/c_smoke"
if ($LASTEXITCODE -ne 0) { throw 'Подготовка C_smoke не завершена' }
& $python @helper check-csmoke
if ($LASTEXITCODE -ne 0) { throw 'C_smoke не прошёл независимую сверку' }
& $python @helper replay
if ($LASTEXITCODE -ne 0) { throw 'Настройки оценки не созданы' }
& $cli replay --period C_smoke --config "$work/replay.json" `
  --run-id reproduction-small-replay --run-dir "$work/evaluation"
if ($LASTEXITCODE -ne 0) { throw 'Оценка не завершена' }
```

`evaluation-preparation` проверяет готовую модель, связывает её с собственными
признаками и B, затем создаёт `post_training` с B12 и `operation=evaluate`.
`check-csmoke` повторяет прямую проверку новых данных; `replay` подставляет их
фактический хеш. Исходы присоединяются после расчёта рекомендаций.

Результат: `$work/evaluation/reports/replay.json` и `replay.md`, таблицы ответов
и сессионных оценок. Для GCS+Rk, P и R в отчёте указаны число сессий с
зарегистрированной целью и Hit@20 среди них. Полнота телеметрии неизвестна;
пустая цель не считается отрицательным исходом. Если параметры интервалов
не обоснованы, сохраните статус `insufficient`.

В сохранённых прежних отчётах разрезы `history=...` считались по хвосту из
не более 20 просмотров, а не по всему префиксу. Их нельзя использовать для
сравнения качества на длинных историях. Эти разрезы не пересчитывались;
общие Hit@20, покрытие, Recall@20 и NDCG@20 от исправления не меняются.

Настройки и подтверждения допуска формирует
[verification/reproduce.py](/src/coveo_recsys/verification/reproduce.py) из текущих
файлов и проверок, без зависимости от прежних `runs/`.

## Измеренные затраты

В новых отчётах сравнения `full_recommendation_timing[policy].recommend_seconds`
содержит сумму времени вызовов `recommend`, без последующих диагностики,
сериализации и записи. Прежний `calculation_seconds` сохраняет старый смысл:
расчёт вместе с неодинаковой для двух моделей диагностикой и её JSON.
В старых отчётах нового замера нет; их чтение выдаёт предупреждение, не подставляя
прежнее время. Ни один из этих показателей не является задержкой HTTP.

Ниже — измерения завершённых локальных запусков на Windows, не прогноз для другого
компьютера. Загрузка, проверки и запись включены в измерения команды, если
не сказано иное. Каталоги ниже — источники локальных результатов, не ссылки
на скачиваемые артефакты.
